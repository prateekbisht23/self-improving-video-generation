# 06 — SQLAlchemy 2.x, Alembic migrations, Postgres features we use

Code: `db/models.py`, `db/session.py`, `db/migrations/`.

## SQLAlchemy 2.x in one screen
```python
class Scene(Base):
    __tablename__ = "scenes"
    id: Mapped[uuid.UUID] = mapped_column(primary_key=True, default=uuid.uuid4)
    start: Mapped[float]                                   # NOT NULL inferred from the type
    description: Mapped[str | None] = mapped_column(Text)  # `| None` means nullable
```
- `Mapped[...]` type hints drive both the column type and nullability.
- A **Session** is a unit of work. `session_scope()` commits on success and rolls back on any exception, which is how each pipeline stage stays all-or-nothing.
- `relationship(order_by=...)` gives `asset.scenes` already sorted.
- `expire_on_commit=False` lets objects stay readable after commit. FastAPI serialises responses after our code returns, so this matters.

## Alembic
```bash
uv run alembic revision --autogenerate -m "what changed"   # diff models vs DB, write a migration
uv run alembic upgrade head                                 # apply
uv run alembic downgrade -1                                 # undo the last one
```
**Always read the autogenerated migration.** It can't know about:
- `CREATE EXTENSION vector`. We added it by hand.
- Postgres **enum types**, which outlive their tables. We drop them in `downgrade()`, otherwise upgrading → downgrading → upgrading again fails with "type already exists".

## Postgres features in play
| Feature | Where | Why |
|---|---|---|
| `JSONB` | `probe`, `audio_features`, `words`, stage `detail` | flexible, still queryable (`->>`) |
| `ARRAY(String)` | `scenes.tags` | small lists without a join table |
| **Generated column** | `search_tsv = to_tsvector('english', search_text)` | the DB keeps the search index in sync |
| GIN index | on `search_tsv` | fast full-text search |
| `pgvector` + HNSW | `scenes.embedding vector(768)` | approximate nearest-neighbour search |
| Enums | asset/stage status | the DB rejects invalid states |

Generated columns may only call **immutable** functions. `array_to_string` isn't immutable, and `to_tsvector` is only immutable with an explicit `'english'::regconfig`. That's why the app writes `search_text` and Postgres derives the tsvector from it.
